Editing that adds energy

Make it creative without making it fake

  • Use a tiny corner chapter label: Request → Feasibility → Payment → Failure → Recovery.
  • Add a restrained “payment gate unlocked” sound when the feasible offer is accepted.
  • Use a one-second red tint or subtle impact sound when the bowl station fails.
  • Freeze for one second around each matching provider-ID suffix so judges can verify it.
  • Use jump cuts for Razorpay loading; never fake the result or cut away before showing the matching Dashboard entity.
  • Keep music low and percussion-free under narration. Silence it during the station failure for contrast.
  • Put captions on every spoken line; many judges watch without sound.

Vercel readiness

Current answer: do not deploy this repository to Vercel yet

The React/Vite frontend can run on Vercel. Vercel also supports Fastify as a Function when its entrypoint is placed at a detected location.

The complete RASOI flow is not Vercel-safe in its current form. It writes the authoritative ledger to local SQLite, starts background timers for payment/refund reconciliation, and keeps process-local lifecycle state. Vercel Functions have ephemeral instances and no durable shared local filesystem.

Required before a full Vercel deployment

  1. Migrate the seven-table SQLite ledger to durable Postgres, such as Neon or Supabase.
  2. Rewrite the database layer and preserve the existing transactional reservation/idempotency guarantees.
  3. Move the Fastify entrypoint to a Vercel-detected path such as src/server.ts.
  4. Replace always-running reconciliation timers with webhook-first processing plus a secure cron/queue and request-triggered reconciliation.
  5. Add Vercel routing/build configuration for the Vite assets and Fastify Function.
  6. Set production environment variables, including the production origin and Razorpay Test secrets.
  7. Change the Razorpay Test webhook to the stable HTTPS deployment URL.
  8. Repeat the complete live Order → Payment → station failure → Refund test on the deployed URL.

Fastest safe submission option: deploy the current full application to a long-lived Node host with a persistent volume. Use Vercel only after the database/lifecycle migration, or use Vercel for the frontend with the API on that long-lived host.
